# Plan 02 — Electron UI: scrub, edit, apply, resolve

Slices 2–3 of `docs/research-2026-09-30.md` §3.10, plus the in-editor half of slice 4's resolve loop, because a prototype that cannot get past a conflict is not usable. Pre-commit hooks at publish, the persistent worktree, formatting, undo, and the mergetool break-out are plan 03.

## Goal

`npm run app -- <repo>` opens one window on the repository's current stack. Clicking a commit shows the whole commit as one scrollable document, every changed file as an editable inline diff against the parent. Editing records a draft for that commit. Apply publishes all drafts; a conflict turns the view into a resolve view for the conflicting commit; after resolving, Apply goes through.

## Tooling

- Electron 44, electron-vite 5 with Vite 7 (electron-vite 5 does not support Vite 8 yet). Three entry points: `src/main/index.ts` (main process, hosts the engine), `src/preload/index.ts` (the bridge), `src/renderer/index.html` + `src/renderer/main.ts` (UI).
- CodeMirror 6: `@codemirror/view`, `state`, `commands`, `language`, `language-data` (lazy-loaded language by filename), `merge`, `search`, `theme-one-dark` for dark mode. No UI framework: plain TypeScript and DOM, which is enough for three panes and a toolbar.
- Scripts: `npm run app -- <repo>` (build and launch), `npm run dev -- <repo>` (electron-vite dev with renderer hot reload). The repo path is the first non-flag argument, defaulting to the current directory.

## Process boundary

- `src/shared/api.ts` declares the API as one type, `SuonetarApi`: every method returns a `Promise` of a discriminated result `{ ok: true; value } | { ok: false; error: { name; message } }`. Errors cross IPC as data because Electron strips thrown errors down to a message; known engine errors keep their class name so the UI can react (`ErrorEditRefused`, `ErrorStale`).
- The main process registers one `ipcMain.handle` per method, each a one-line call into `Session`. The preload exposes `window.suonetar: SuonetarApi` via `contextBridge`; the renderer has no Node access (`contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`).
- Buffers cross as `Uint8Array`; the renderer decodes text with `TextDecoder` and treats a file as binary if it fails strict UTF-8 decoding or contains NUL, showing "binary file, not editable" instead of an editor.
- API surface: `state()`, `generation()`, `commitFiles(oid)`, `fileVersions(oid, path)`, `blob(oid)`, `draftSetFile(oid, path, content | null)`, `draftSetMessage(oid, message | null)`, `draftDiscard(against)`, `draftConfirm(against)`, `preview()`, `apply()`, `resolve(inputs, markerTree, choices)`.

## Engine changes

- `Session.blob(oid)` for reading conflict stages.
- **Saving onto a commit that was rewritten meanwhile.** `draftSetFile` and `draftSetMessage` currently throw `ErrorStale` when the commit is no longer in the stack. Instead they accept any commit that still exists in the object database: the draft is keyed to it and, since that commit is not in the stack, `draftsResolve` classifies it as `rebased` (or `orphan`/`conflict`), so the user confirms it onto the rewritten commit. An edit typed while Claude Code rewrote the stack is therefore never rejected and never lost; it goes through the existing confirmation path. `ErrorStale` remains only for commits that do not exist at all.

## Layout

Three regions in one window:

- **Top bar:** branch and base, the draft count, the Apply button with a one-line preview summary ("rewrites 4 commits", "conflict in commit 3"), and a status line for results and errors.
- **Left: the stack.** One row per commit, newest at the top (as `git log` reads): short SHA, subject, badges for *draft*, *published* (editing it means a force-push later), *empty*, *signature will be dropped*. A note at the bottom when the stack was cut at a merge, and the left-behind branches if any. Drafts that are `rebased`, `conflict`, or `orphan` are listed under the stack with Confirm / Discard buttons and their reason.
- **Main: the commit document.** The commit message in an editable text area at the top (a message draft on change), then one section per changed file in path order: a header (path, status, +/−, draft badge, "revert file" to drop this file from the draft) and an editor below it. Unchanged regions are collapsed (`collapseUnchanged`). A file list at the top of the document jumps to a section.

## Editing

- Each file section is a CodeMirror `unifiedMergeView`: `original` is the file at the commit's parent, the document is the file with the commit's draft applied. Deleted lines show inline and are not editable; accept/reject controls per chunk are on, so rejecting a chunk reverts that part of the commit, which moves the change to the commit above on replay.
- Added files have an empty original; deleted files show the parent's content with a "file deleted in this commit" header and a "restore" action; binary files and refused paths (symlink, submodule, filtered) show a note instead of an editor.
- Language by filename via `@codemirror/language-data`; line numbers, search, bracket matching, history, and the default keymap.
- Editors are created lazily when their section scrolls near the viewport (`IntersectionObserver`), so a commit touching hundreds of files opens instantly. A section is never torn down while it has unsaved changes.
- **Saving:** every change schedules a save of that file 500 ms after the last keystroke; switching commits, applying, or closing the window flushes pending saves first and waits for them. The document's edited state is always the draft on disk within half a second.
- **View mode:** a toggle switches the document between unified and side-by-side (`MergeView`) for wide diffs.

## Navigation

- Click a commit, or `Alt+↑` / `Alt+↓` for the previous/next commit.
- `Alt+PageDown` / `Alt+PageUp` jumps to the next/previous file section; `Ctrl+Alt+↓` / `Ctrl+Alt+↑` goes to the next/previous changed chunk across the whole document (CodeMirror's `goToNextChunk` per editor, continuing into the next section at the end).
- The application menu is removed so no Electron accelerator steals editor keys (`Ctrl+W` included); `F12` toggles devtools, `Ctrl+R` reloads.

## Live follow

The renderer polls `generation()` once a second. On change it flushes pending saves, then reloads the state; the selected commit is re-selected by OID, or by author line if it was rewritten, else the nearest remaining position. Open sections keep their scroll position when the commit is unchanged.

## Apply and resolve

- **Apply** flushes saves, calls `apply()`, and handles every result kind: `published` (refresh, status "published"), `nothing`, `refused` / `locked` / `moved` (status line with the reason; `unreverted` files are listed prominently), `interrupted` (a blocking banner pointing at `docs/recovery.md`), `drafts-need-attention` (scrolls to the drafts list), `conflict` (enters the resolve view).
- **Resolve view** replaces the commit document for the conflicting commit. Header: "Commit *N* conflicts with the changes below it", with the three sides named by meaning: *below* (the rewritten parent, which contains your edits), *this commit*, and *base* (the original parent).
  - Content conflicts: the marker file from `markerTree` in a plain editor. The raw tree OIDs in the marker labels are rewritten to *below* / *base* / *this commit*. Each conflict block gets a small widget with **Keep below**, **Keep this commit**, **Keep both**; the text stays freely editable. Blocks still containing markers are counted in the header.
  - Structural conflicts: the conflict message, and one button per available side (**Keep below's version**, **Keep this commit's version**, **Delete**), which choose the path's content from the stage blobs; junk `path~<oid>` entries git leaves for directory/file conflicts are deleted automatically once the user has chosen for the real path.
  - **Save resolution** is enabled when no markers remain and every structural path has a choice; it calls `resolve()` and then `preview()` again, which either reaches the next conflict or turns Apply green.
- The marker parser and the block choices are a pure module (`src/renderer/conflicts.ts`) with unit tests: parse `merge`, `diff3`, and `zdiff3` style blocks, apply a choice to one block, relabel, detect remaining markers.

## Testing

- Unit tests (Vitest, node environment) for `conflicts.ts` and for the IPC result wrapper.
- Engine tests for the two engine changes (`blob`, saving against a rewritten commit).
- The rest is UI without a test seam; it is verified by launching the app against a scratch repository and exercising: scrub, edit, save, commit switch, apply, conflict, resolve, apply, rewritten-under-you, refused because of a dirty file. That smoke is reported explicitly rather than claimed as coverage.

## Revisions after hostile review

A hostile review (Opus, 2026-09-30) verified the plan against `@codemirror/merge` 6.12.2, `@codemirror/commands`, electron-vite 5, and git 2.55. All blocking objections are accepted; this list supersedes the sections above where they conflict. Engine-side items were done in the engine revision already committed (see plan 01, "Revisions after code review"): OID-based `commitDocument` / `draftDocument` / `blob`, saves against rewritten commits, fixed `generation()`, per-record resolutions with stage/delete/directory/content choices, store reflog, `elsewhere` drafts with `draftAdopt`.

**Data safety in the renderer**

1. *Own saves must not trigger reloads that clobber typing.* When the selected commit's OID is unchanged, a refresh updates metadata only (stack, badges, drafts list) and never replaces an editor document. The poll is a chained `setTimeout`, not `setInterval`.
2. *Destroying an editor always flushes it first* (commit switch, refresh to another commit, view change, window close). No "unless unsaved" exceptions.
3. *A failed save keeps the section dirty*, shows it prominently, and retries; commit switch and close are blocked with a prompt while any buffer is dirty or a save is failing. Files with a `refusal` open read-only.
4. *Close* goes main `close` → `preventDefault` → IPC "flush" → renderer acknowledges → `win.destroy()`. `Ctrl+R` goes through the same flush. `will-navigate` is prevented and `setWindowOpenHandler` denies, so a dropped file cannot navigate away.
5. *During Apply and resolve* the UI shows a busy state and all editors are read-only; close is blocked while an Apply runs.
6. *Text codec* (pure module, unit-tested): decode strictly as UTF-8 with `ignoreBOM: true` and remember the BOM; detect line endings, set `EditorState.lineSeparator` for CRLF files; files with mixed or CR-only endings, invalid UTF-8, or NUL bytes open read-only. Encoding reproduces the original bytes exactly when nothing was edited.
7. *Autosave scheduler* (pure module with injected timers and save function, unit-tested with fake timers): 500 ms debounce per file, in-flight tracking, flush that awaits everything, failures retained and retried.

**Draft states**

8. Every draft is viewable before it is discarded: `draftDocument(against)` in a read-only view with the draft's branch shown; Discard asks for confirmation. A commit with a pending `rebased` draft shows that draft's content read-only with Confirm / Discard, and is not editable until one is chosen. `elsewhere` drafts get Adopt / Discard.

**Editor details**

9. *Keys* are handled in one window-level `keydown` listener in the capture phase, chosen not to collide with CodeMirror's default keymap (`Alt+↑/↓` move lines; `Mod+Alt+↑/↓` add cursors): `Alt+PageUp` / `Alt+PageDown` previous/next commit, `F7` / `Shift+F7` next/previous change across the whole document (as in Rider's diff viewer), `Ctrl+Alt+PageDown/PageUp` next/previous file. Cross-document chunk navigation is built on `getChunks` and the section order, creating a target section synchronously if needed. `Ctrl+=` / `Ctrl+-` / `Ctrl+0` zoom.
10. *Reject only*: `mergeControls` in function form shows Reject and hides Accept (Accept edits the never-saved original side and would hide the change). Rejecting every chunk of an added file deletes the file. A deleted file's editor is read-only, with a Restore action.
11. The side-by-side `MergeView` toggle is deferred.
12. The stack is listed oldest at the top, as `rebase -i` does; "next commit" is the one above in history, below in the list.
13. A per-file "show my edits" toggle switches the diff's original from the parent to the commit (original = commit, document = draft).
14. Commits above a drafted commit are shown against their current parent; a banner says their diff does not yet include drafts below.
15. Large files: sections over 5,000 changed lines, files over the 4 MiB engine limit, and lockfiles / `linguist-generated` paths start collapsed with a click to expand.
16. `preview()` runs on demand only: when Apply is clicked and after each resolve. The top bar otherwise shows the draft count.

**Resolve view**

17. Driven by conflict records, not paths: one row per record with choices by type — content (the marker file in an editor with Keep below / Keep this commit / Keep both per block, relabelled; saved as content), modify/delete (keep or delete), directory/file (keep the directory: delete `d~X`; or keep the file: delete directory `d`, take `d~X`'s stage as `d`, delete `d~X`), rename/rename (keep one side or both), anything else (keep as shown, or pick a stage). Raw OIDs are relabelled in markers, messages, and paths. Marker detection counts only blocks found at load and has a "save anyway" escape (`markersAllowed`). The view is named generically ("needs attention") so plan 03's hook failures can use it.

**Build**

18. The preload is built as a single CommonJS chunk (`format: "cjs"`) since a sandboxed preload cannot load ESM. Scripts end in `--` so the repo path reaches Electron, and a relative path resolves against `INIT_CWD`. Separate tsconfigs for main+preload (node) and renderer (DOM). Pin `vite@7`. IPC wire types use `Uint8Array`, converted to `Buffer` in the main-process handlers.

**Testing**

19. Unit tests for the text codec, the autosave scheduler, the marker parser and block choices, and re-selection after refresh; the remaining UI is verified by a scripted smoke run that includes a CRLF file, a filtered path, a symlink conflict, a directory/file conflict, a Claude rebase during a save, closing with a pending save, and Apply with signing.

**Not adopted:** a single-instance lock per repository (the store's compare-and-swap already turns a second window's conflicting write into a failed save, which item 3 surfaces); a CSP beyond Electron's defaults with `sandbox` on (the renderer loads only bundled code).

## Notes from implementation

- Line endings: rather than `EditorState.lineSeparator`, the codec gives the editor LF text and restores the file's CRLF on encode. Byte-exactness is the same, and pasted text with either ending splits into lines normally.
- Restore and revert go through a new engine call, `draftRestore(oid, path, "commit" | "parent")`, which copies the tree entry (mode included) instead of writing content, so a restored symlink or executable keeps its mode.
- `linguist-generated` paths are not collapsed yet (that needs an attribute query per document); lockfiles by name, files over 5,000 lines, and files over the engine limit are.
- The page carries a restrictive CSP meta tag after all; it costs nothing.
- Read-only editors stay focusable (`readOnly` without `editable: false`) so the cursor and F7 navigation work in them.
- A `beforeunload` guard cancels any unload not preceded by the flush (a page-initiated `window.close()` skips the main-process close handshake).
- Smoke run (scripted over the DevTools protocol under Xvfb): scrub and edit two commits, CRLF edit kept byte-exact, content conflict resolved with "Keep both", signed apply of three commits, modify/delete and file/directory conflicts resolved, filtered path read-only, edit typed during an external rebase kept as a rebased draft and confirmed, window closed within the autosave debounce with the edit saved, revert chunk / show my edits / revert my edits / message edit, orphaned drafts viewed and discarded, apply refused over an uncommitted change in the worktree with the change left intact.

## Revisions after code review

A hostile code review (Opus) found three blocking problems, all fixed:

- A keystroke during "Revert my edits" could save the pre-revert text over the revert. Saves now go through the section's live editor, and every change that replaces editors runs with the view inert after flushing (`CommitView.#rework`); restoring rebuilds the whole view.
- A draft made on another branch (Claude Code switching to a copy of the branch) was blended into the commit document and taken over by the first keystroke. The engine now keeps other branches' drafts out of the document and refuses to extend them; the UI shows the commit read-only with Adopt / Discard.
- Restoring across a file/directory change silently dropped drafted files (`update-index` replaces a directory with a file without complaint). The engine refuses such writes, for `draftSetFile` as well.

Should-fix items adopted: marker parsing matches marker length per block (a Markdown underline inside a block no longer splits it) and relabels only marker lines; one "can have an editor" rule for binary and too-large files; expanding a collapsed section builds its editor; state is re-read after every flush before choosing what to show, via a pure, tested `viewDecide`, which also removed double builds; stack rows select by OID; `op` reports its own failures; discarding unsaved edits is offered only when the view is being left, retries are held while the user decides, and a discarded in-flight save is forgotten; close joins the operation queue and the session closes only when idle; a hung page can be force-closed and a crashed one reloads; message and "empty added file" rules are pure and tested; Apply previews first and asks before rewriting pushed commits or dropping signatures; modals make the page behind them inert; IPC refuses other senders, `blob` takes only object ids (with `blobAt` for paths), channel names come from one helper, and handlers are tested against a fake session; the dev-server URL is honoured only under `electron-vite dev`; Node globals are lint errors in the renderer.

Deferred:

- `commitDocument` still ships every file's three versions at once; a list-then-fetch API is worth adding when plan 03 needs per-file operations anyway.
- A generic main-to-renderer event channel (for progress and hook output) is designed with plan 03.
- `ResolveView` is specific to merge conflicts; hook failures will get their own view or a record-kind union.
- Wire types still come from engine modules; the lint rule stops Node globals from creeping into renderer code instead of duplicating the types.
